## 1. 设计方向与适用范围

**平台整体以 Cyber 工作台的完整视觉语言为设计标准，替换不合适的旧 UI，而不是寻找某个功能点照抄或仅给复测页面换色。** 这是 2026-10-15 用户再次明确的方向：页面布局与比例、密度、留白、字体、按钮、输入框、表格、导航、菜单、弹窗、反馈状态和细节应形成同一种观感。项目、工作区、漏洞成果、复测、资料、模型、Worker、系统设置及其弹窗／浮层均受此标准约束；登录、空态和错误页也不能成为另一套皮肤。

现有实现只提供业务能力和技术基础，不是外观不可替换的前提。保留可靠逻辑，不以“沿用原风格”为理由保留丑旧布局、页面私有覆盖或不协调的共享默认值。**参考设计体系，不复制对方业务功能；规范覆盖全站，实际改动按本轮明确范围落地。**

目标是长期使用的专业工作台：紧凑但不拥挤、层级明确、阅读舒适、操作位置稳定。参考的核心是近黑／炭灰的表面层次、柔和蓝色强调、细边框、克制圆角、清晰文字，以及与任务相配的表格、主从阅读和一体化编辑布局。

- **统一设计语言，不强制统一页面形状。** 任务列表以表格为主，资料阅读可以左列表右正文，运行工作区围绕当前工作与成果组织；不能把一个参考页面套到所有功能。
- **信息与操作优先，装饰退后。** 不用巨幅标题、渐变横幅、霓虹、发光边框、满屏统计卡片或多层卡片表达“高级感”。
- **不照搬业务机制。** 不因参考站存在组织、套餐、配额、资料分类或任务步骤就引入它们；不得把内部协议和无必要配置前置给用户。
- **保留 Arena 身份与数据边界。** 不复制 Cyber 的品牌、Logo、账号、水印、付费素材、登录态或业务内容。界面使用简体中文和 Lucide，保留必要技术术语，不新增 i18n 或另一套图标／组件库。
- **规范不是全仓改造授权。** 新增或修改界面时按本规范推进；共享主题调整与存量页面统一需要明确实施范围，不借一处功能改动重写整个前端。

## 2. 参考依据：观察与设计约定分开

参考站为 <https://cyber.chainreactors.cn>。以下表格保留 [漏洞复测方案第 9.1 节及第 13 节](specs/vulnerability-retest-design.md)中的 2026-10-14 历史观察；第 2.1 节是 2026-10-15 看图记录，第 2.2 节是 2026-10-16 已登录现场观察。三者不能混写成同一次实测，更不能代替 Arena 的实现验收。

| 参考范围 | 已记录的观察 | Arena 采用方式 |
| --- | --- | --- |
| `/tasks` 任务页 | 紧凑标题与操作、筛选、一整块满宽表格 | 项目／任务／复测等管理列表采用相同信息层级，不改成装饰卡片墙 |
| `/references` 资料页 | 左侧列表、右侧正文阅读 | 资料、知识、输入与证据阅读按需要采用主从布局，不泛化成所有列表的结构 |
| 新建任务弹窗 | 宽编辑区域，工具条／正文／资料底栏组成一个整体 | 正文驱动的创建／编辑动作使用一体化编辑器与稳定底部操作栏 |
| Materials 浮层 | 候选资料与已选资料分区 | 有实际候选来源时才分区；只有上传文件时展示真实文件列表，不虚构资料库 |
| 工作台视觉 | 近黑／炭灰、柔和蓝、细边框、清晰小字号、克制圆角和阴影 | 作为全站共享视觉基线，不复制站点品牌或业务对象 |
| 未观察的功能 | 没有足够依据证明其运行详情、管理设置或全部响应式布局 | 下文对这些页面的组织是 Arena 的设计约定，不宣称逐页还原 Cyber |

不以“使用了深色主题”“有蓝色按钮”或“改成左右两栏”代替整体一致性。参考站若变化，以经过确认的设计方向为准，不自动追随线上每次改版。

### 2.3 2026-10-16 报文补充实施后的现场对照

用户反馈第 15.9 节实施后仍不是预期效果。本分析会话再次只读查看已登录 Cyber 的漏洞详情“基本信息”中的 **HTTP 流量折叠条目**，实际展开既有证据并查看截图／computed styles，没有点击验证修复、保存图片、复制、原始调用或目标链接，没有向被测目标发送／重放请求；查看页面仅正常读取既有业务数据。此次终于核实到的是**证据条目内的报文卡片**，不是“每条漏洞记录展开完整详情”；两者不能混为同一参考。

在 1440×1000 浅色视口、约 619px 宽的样本报文卡片中，实际观察为：

- 单个外框，约 12px 圆角；顶部约 38px 的“HTTP 证据＋地址摘要”栏，下方两侧等宽、中央细分隔线。
- 每侧约 49px 标题工具栏：请求／响应、方法／状态码小标记、带短下划线的 Raw、靠右低强调复制。没有本样本中可见的搜索／换行／放大文字按钮墙，也未看到 Pretty；Raw 是标签，不据此外推参考站已实现可切换模式。
- 两侧报文正文顶部／底部对齐，样本均约 353px 高，独立滚动；不是按左右实际行数形成两个不同高度的编辑框。此处只证明该样本，不推出 Cyber 所有报文使用同一固定高度。
- 等宽正文实测 12px／19.5px 行高，默认软换行；约 35px 行号区，有轻微底色与右分隔线，正文左侧约 12px 内边距。请求方法、头名称及响应状态有明确但克制的颜色区别。
- 浅色表面为白正文、淡蓝灰标题／行号区域、细蓝灰边线。此轮没有查看其深色报文，也不复制品牌、账户、水印、报文正文或原始资料。

随后用户确认两站均已登录，本会话实际打开 Arena 本机入口的“成果列表 → 既有漏洞行内详情”，只读查看已有 HTTP 证据；未发起复测、修改漏洞状态、复制／下载原件、访问目标或读取凭据。两站均在浅色下观察：

- Arena 1440×1000 视口的报文卡片约 1111px 宽；每侧标题高 37px，另各占一行 27.5px 的“仅支持完整 JSON…”说明，即使只是普通非 JSON 报文也常驻显示禁用 Pretty 和该说明。
- 请求／响应 Monaco 视窗分别约 214px／480px 高。请求正文在卡片中途结束，下方约 266px 留白与正文底色不同；虽然已经共用外框，视觉仍像两个独立编辑器。正文底色实测 `rgb(246,248,251)`，标题白色，与参考站“白正文、淡色标题／行号”的层次方向不同。
- 当前正文实测 14px／23px；行号槽已约 35px 且有分隔线，正文紧接其右边界，缺少参考的约 12px 阅读内边距。HTTP 高亮已经存在，不是待从零添加。
- “关键证据＋来源”、交互选择按钮、“同一交互标题＋来源”连续出现；单一主交互也重复显示。这里应合并重复身份，不是再追加一层共同标题。
- 将 Arena 视口改为 960×1000 后，实际卡片约 639px 宽，响应侧已 `display:none`，改为请求／响应切换；Cyber 此次约 619px 的卡片仍同时显示两侧。比较依据是卡片可用宽度，不是要求两站整页同布局。观察后已恢复 Arena 1440×1000 视口。

这纠正了第 5.8 节初稿把“Burp 感”主要翻译成 Raw／Pretty／搜索等功能清单的偏差：功能可保留，但默认视觉首先要对齐**紧凑的协议标题、清楚的双栏边界、平齐的阅读区域和低强调操作**。原方案要求的默认不换行、各侧独立高度也须替换，不能将照旧方案实现说成实施者漏做。本次已完成上述浅色样本的实际对照，不代表所有消费者、深色或全部断点验收；下一轮设计见第 5.8 节及重设方案第 15.10 节，实测尺寸是依据，不机械复制 12px 或扩大到全站缩字。

## 3. 视觉基线与共享 tokens

### 3.1 颜色与表面层次

以下深色数值来自历史观察，当前源码已采用主要基础色，见第 2.1 节纠正；不是本轮深色实测或必须逐像素复制的品牌色规范。浅色现场参考见第 2.2 节。实际实现集中映射到共享语义 tokens，保证正文、控件、浮层及不同状态的对比度；不得在各功能页重复硬编码。

| 语义 | Cyber 观察值／特征 | Arena 使用约定 |
| --- | --- | --- |
| 页面底色 | `#101114` | 最低层画布，覆盖主工作区域，不在每个页面另造背景 |
| 侧栏 | `#15171b` | 与画布轻微区分，靠表面和细分隔线组织，不用厚阴影 |
| 面板／弹窗 | `#1e2025` | 承载主要内容；输入区、编辑区可比面板低一级，避免面板中反复嵌套面板 |
| 主强调色 | `#65a1e6` | 主要按钮、选中态、链接和焦点；不是所有标题／图标都染蓝 |
| 选中导航 | 蓝色约 15% 透明底 | 以浅底、文字和图标共同表达，不能只靠一条难辨认的线 |
| 主文字 | `#ebedf0` | 正文与关键值；次级文字用现有语义 token，不能降到难以阅读 |
| 边框 | 低对比细线，弹窗可带轻微蓝灰 | 区分相邻层次；默认不是发光描边，焦点边界必须清楚 |
| 状态色 | 与品牌强调分开 | 成功／警告／错误沿用语义色和文字，蓝色不代表成功或漏洞已确认 |

- 深色模式以这组视觉关系为参考，浅色模式保持同一结构、密度和交互，用现有浅色语义色实现足够对比；不把深色十六进制值机械套到浅色。
- 保留用户主题偏好，不为参考 Cyber 强制切换全站主题。一次局部功能改动也不能偷偷改默认主题。
- 阴影主要用于弹窗、Popover 等浮层；平面列表与表单优先靠留白、表面明度和细线。避免大面积模糊、玻璃效果和层层高投影。
- 当前主题与目标有差距时，在明确的共享样式实施范围内统一 tokens／组件；不要持续复制“某页面专用 Cyber 主题”。

### 3.2 字体与信息层级

保留现有字体栈，不为仿站下载字体。以下是全站目标尺度，按中文内容与阅读任务选择，不为凑参考尺寸压缩文字。

| 场景 | 默认目标 | 用法 |
| --- | --- | --- |
| 页面主标题 | 约 20px、字重 600 | 简短名称，不写成长段说明，不在普通工具页使用营销式大标题 |
| 区域标题 | 16px、字重约 600 | 区分内容分区，不让每个字段都像一个标题 |
| 列表／控件正文 | 14px、行高约 1.5 | 名称、选项、按钮与主要状态可直接阅读，不用缩字换密度 |
| 报告／结论／长正文 | 通常 15px 左右、行高约 1.75；复测结果局部约 14px／24px | 阅读优先，段落有间距；文字行长约 65–85 个等宽字符，报文区可更宽；复测结果例外见第 5.3 节，不缩小创建预览或全站正文 |
| 表单标签 | 13–14px、中等字重 | 属于操作必读信息，不与弱化说明混用，不能统一压成 12px 灰字 |
| 时间与辅助信息 | 12px | 仅用于确有用途的次级内容；不是给每个字段添加说明的许可 |
| 低频技术元信息 | 11px 仅用于按需诊断 | 正常结果与配置表单不出现成片 11px 文本；不用于按钮、禁用原因或用户必须阅读的内容 |
| ID／报文／代码 | 现有等宽字体 | 与中文说明分层，长串可换行或在自己的区域横向滚动 |

**文案克制，减少小字说明（2026-10-15 用户补充）：**

- 页面通过准确标题、字段标签、状态和操作表达用途，不在每个区域、字段或按钮旁常驻一段小字解释。能从界面直接理解的内容不重复说明，不把设计文档、内部协议或操作教程搬到正常页面。
- “减少小字”首先是删除冗余文案、合并重复信息和调整层级，不是继续缩小字号、降低对比度或把正文压成标签。报文、业务结论、必要条件和错误原因使用可读的正文尺度。
- 正常状态保持安静；帮助说明按需查看，只有确实影响当前操作的缺项、失败、未知状态和重要边界才在对应位置显示简短提示。不能为了简洁隐藏受理结果未知、关键证据缺失、禁用原因或当前任务真实需要的边界信息，也不能只用 tooltip 承载这些信息；不因此新增无必要的目标表单或重复确认。
- 同一提示在一个合适的位置表达，避免标题副文案、信息条、字段帮助与页脚重复出现。长诊断、技术 ID、完整时间、内部来源关系及附件清单仅在确有用户任务需要时提供次级入口，否则不展示；不挤占主要工作内容，也不要求每页为后台字段保留入口。
- 精简的是界面说明，不是业务事实与证据原件。原始报文、用户输入、历史结果和限制在原有权限边界内完整留存；**后台保存不代表每个页面必须提供资料、文件、JSON 和诊断入口**。允许从具体用户页面彻底移除不服务当前任务的内容类别，而非机械改成更多折叠框。原件由必要的既有受控读取路径消费，预览、排版不能改写它们，也不能以模型摘要冒充原文。

### 3.3 间距、尺寸与形状

下列除明确标注的历史观察值外，都是 Arena 的设计约定；通过现有 tokens／组件尺寸表达，不逐处硬编码。

- 使用现有 4px 基础间距：4／8／12／16／24／32。默认页面内边距约 24px，窄屏约 16px；区域间距 16–24px，关联控件间距 8–12px。
- 侧栏宽度参考 248px，选中导航高度约 39–40px；保留已有折叠／移动导航能力，不为了一个页面反复改全站 Shell。
- 普通控件采用紧凑、易命中的高度，通常 32–36px；触控场景扩大操作区域，不以缩小图标和点击区换密度。
- 表格正文行通常 48–56px，允许单行紧凑或双行扩展；这是 Arena 建议，不是 Cyber 表格行高实测。长内容不撑坏整行，关键信息仍可完整访问。
- 控件圆角以约 8px、标签约 6px、主要面板约 8–12px 为参考；按现有语义尺寸复用，不把所有元素做成胶囊。普通状态 Badge 不做大按钮外观。
- 以细边框、合适留白和稳定对齐形成层级，不靠给每块正文套 Card。一个主要任务区域优先一个外层容器，内部用分隔和标题组织。

### 3.4 简洁与完成度的可检查标准

- **主次不是靠小字堆出来的。** 首屏只有对象名称、必要状态、主动作及主体；没有数据的可选项不显示“无外部编号”等占位说明，没有真实限制时不留空标题。执行完成后收起正常运行基础设施信息，不让回收状态、内部 ID 占用报告上方多行。
- **每个信息只出现一次。** 标题区已表达的业务结果不在正文前再叠一排同义 Badge；用户要求三段结果，就只有三段结果，不把删掉的输入／文件／配置改藏到一排折叠框里。
- **表面关系整体替换。** 已授权视觉改动时，共享深色画布、侧栏、主面板、浮层、输入区、强调色和文字同时按第 3.1 节协调；不能只把主按钮改蓝。浅色使用同一柔蓝体系但单独保证对比度，保留主题选择；不强制切深色。Monaco、Select、DropdownMenu 与 Portal 也要检查实际颜色。
- **控件不是一片细线小字。** 主要按钮／输入约 36px 高，菜单项约 36px，图标点击区不小于 32px；表单标签 13–14px，正文 14px。HTTP 报文专用阅读密度见第 5.8 节，不将它扩散到报告、表单或配置正文；其他代码阅读沿用原可读尺度。少数既有紧凑尺寸可用于次要动作，不把它当主要表单默认。
- **菜单和正文有各自边界。** 行尾三点与标题点击独立，底部行菜单向可见区域避让，不被表格边框裁切；危险项以分隔和文字表达。关闭菜单焦点回到触发器，删除该行后回到下一合理位置。
- **结果是一篇可读报告，不是字段检查器。** 使用连贯阅读区域、左对齐的小标题与段落；复测三段始终纵排并有清楚边界，具体见第 5.3 节。请求／响应只在对应步骤展示，不同时再铺证据列表、路径、ID 和全文。报文宽度足够时并排，不足时纵排或切换；保持缺侧和预览不完整提示，不能把原始内容翻译或截断成假完整报文。
- **配置像表单，不像说明文档。** 正常状态不常驻“为什么这样设计”的段落。主要配置直接编辑，高级参数收起；生效范围只在保存区表达一次，真实阻塞原因在相应字段或状态旁用正文显示，不靠灰色小字或 tooltip 解释禁用。

这些是实施验收依据，不是本分析轮已测得的当前 UI 指标。查看实际截图时同时检查比例、留白、对齐与重复信息，不能只逐项对上 CSS 数值便宣布“简洁高级”。

## 4. 全站骨架与导航

- 使用稳定的应用侧栏、页面标题区和主内容区。侧栏承担全站导航，页内 Tabs 承担同一对象／任务的内容切换，面包屑承担层级与返回；不要重复三套相同菜单。
- 普通页面标题左侧为名称与必要短说明，右侧为最主要动作；筛选或子导航在下一层。标题、工具条、表格和正文的左右边线对齐。
- 页面通常保留一个明显的主要动作，其余动作降为次要按钮或菜单。危险动作与高频操作分开，不把删除、停止等藏在只能靠颜色识别的图标中。
- 侧栏、面包屑、命令面板与页面标题使用一致中文名称；显示权限与服务端授权分别正确，隐藏菜单不代替鉴权。
- 内容宽度按任务分配：管理表格利用可用宽度，正文阅读控制行长，配置表单限制到舒适的编辑宽度。不能给所有页面强加同一个窄容器，也不能让单列短表单横跨超宽屏。
- 配置只提供完成任务所需的入口，不增加形式化前置步骤。例如专用复测 Worker／模型在复测配置中管理，不能为了“页面一致”强制用户去创建普通 Worker 或项目组。

## 5. 按任务采用页面模式

### 5.1 管理列表：紧凑满宽表格

适用于项目、计划、复测、漏洞以及需要多字段比较的模型／Worker／配置条目。

- 基本顺序为“标题与主操作 → 筛选／搜索 → 一块 DataTable → 分页”。不在列表前默认堆统计卡片；只有真实、直接服务当前动作的汇总才保留。
- 名称列是阅读入口，状态／结果／时间对齐稳定；次级 ID、来源和说明弱化，不与名称争夺空间。长名称可截断，但能打开详情或以可访问方式查看完整内容。
- 搜索、筛选和排序须有真实数据能力，明确精确匹配或全文检索；没有接口支持就不画假搜索框或无效页签。
- 行点击与行内按钮各自独立，不嵌套交互元素。打开详情后返回，保留合理的筛选、分页、选中与滚动位置。
- 数据少不等于应该换成大卡片。只有对象以独立内容块阅读且不需要逐列比较时才选择卡片布局。

### 5.2 资料与证据：主从阅读

适用于知识资料、文件材料、输入原件、报告与证据切换。

- 左侧是可扫描的资料导航，右侧是主要阅读区；列表不应占掉正文的大部分宽度。各自有清楚的滚动归属，不能让多层滚动相互争抢。
- 顶部清楚展示当前文件名、资料身份、可用操作和必要状态。原件、派生材料、历史证据与本次证据不能只靠颜色区别。
- 文件清单、下载、预览和原字节访问分别按真实能力提供。预览截断要注明；不能把摘要、替换字符或缩略图冒充完整原件。
- 只有一个资料或可用空间不足时可以单栏阅读，不为凑左右布局保留空列表。窄屏以“选择资料 → 阅读 → 返回资料列表”的明确路径替代被压扁的两栏。

### 5.3 项目／运行详情：当前工作与结果优先

此处是 Arena 的业务布局约定，不是声称已观察到 Cyber 对应详情页。

- 顶部集中对象名称、简短真实状态、核心操作；第一屏回答“当前在做什么／为什么等待、已经得到什么、下一步能做什么”。
- 用少量有业务意义的 Tabs 或稳定分区承载结果、输入、执行记录和历史。不是每个字段一张卡片，也不把全部日志和 JSON 平铺在首屏。
- 运行时优先展示实际活动与已有成果；终态优先结果、证据和限制。没有合法结果时明确说明，不用空结果面板或假进度填满屏幕。
- 证据／过程需要同时对照时可以分栏；纯阅读详情不强制长期保留侧边诊断栏。宽屏多栏应有实际阅读收益，窄屏按优先级降为单栏。
- **复测结果三章始终纵排（2026-10-18 用户要求）。** 一、结论→二、关键证据→三、测试过程在所有容器宽度保持单列，替代旧宽态一二 5:4 并列。各章正文放入有细边框的只读阅读区，段间约 12–16px、内边距约 16–20px，避免大外框叠多层 Card；标题约 16px，结果正文局部约 14px／24px，长文自然增高不裁切。这是阅读区域，不是可编辑 textarea 或整篇 Monaco；保留条件／限制、历史 Markdown、证据跳转和唯一当前步骤阅读器，不展开所有步骤全文。此规则不缩小创建表单预览／全站正文，也不取消报文请求／响应宽态双栏。
- 服务健康、执行状态、业务结论、环境回收是不同事实，分别表达；进程启动不代表模型正常，停止请求已接受不代表执行已停止，未复现不代表已修复。
- **项目主状态直接来自 `project.status`，不由 runtime 健康度替代，也不是 runtime 出错才 fallback。** 列表和工作区标题同源显示“待启动／进行中／已暂停／已结束／已完成”等简短标签；“进行中”只表达项目处于 active，不声称 Worker 已启动或模型健康。准确映射以当前实际枚举为准，不能虚构状态。
- 删除任务列表整页“运行状态未更新”、逐行“上次状态”和额外原因，以及工作区标题旁同类 runtime／Dispatcher 告警。不改名挪到 tooltip、折叠框或状态副标题继续常驻，不再让诊断刷新失败覆盖已读取的项目状态。
- 这不改变执行安全语义：项目“已暂停”不证明进程已退出或环境已回收；runtime 仍为已有运行诊断及确实依赖它的操作服务，保持有效期、归属、服务端裁决。创建受理未知、正在提交／停止确认、真实动作失败、授权／资料修改／报告等待等影响当前动作的边界留在该动作位置，不回灌为每个项目的常驻解释。
- 项目元数据本身加载失败仍在读取位置明确反馈，不能伪造新状态或把缓存说成刚确认。技术 ID、完整错误与协议原文仅在必要的既有诊断入口提供；“未知／旧快照在折叠态可见”的规则适用于所展示的执行观测和未确认请求，不要求项目列表为不再展示的 runtime 另建诊断 UI。

### 5.4 创建与编辑：正文和主要输入优先

- 可在当前列表上下文完成的创建／编辑优先使用 Dialog；需要长期编辑、复杂深链接或大规模资料操作时用独立页面。共用输入与提交逻辑，不维护两套同义表单，不强制所有创建都改弹窗。
- 正文驱动的大弹窗参考约 896px 宽；这是历史参考值，不是所有 Dialog 的统一宽度。简单确认与短表单按内容使用已有较小尺寸，不能为了统一而撑大。
- 布局分为稳定标题栏、可滚动内容区、底部操作栏；弹窗高度受视口约束，不写死参考截图高度，保存／取消始终可到达。
- Markdown 编辑器把工具条、编辑／预览、正文、资料底栏置于一个外边框内。正文内边距可参考 18–20px，正文约 14px／26px 行高，初始编辑高度约 180–240px；内容较多时允许扩展，不让工具条抢占主要区域。
- 文件、附件数量和上传状态在资料入口收起后仍可见；浮层关闭不丢失正文、File、上传队列或已选项。只有实际存在候选资料时才显示候选／已选两区。
- 必需输入可见，高级参数按需展开；相关字段可以并排，长正文和错误不要塞在窄列。避免为了制造“流程感”把一个简单动作拆成多步向导。
- 离开有未保存内容的编辑区时准确提示；上传中、请求提交中、受理结果未知分别处理。未知结果不能悄悄生成新请求或显示假成功；不得将敏感正文默认写入浏览器持久存储。

### 5.5 配置页：配置一处，结果可理解

- 默认先显示主要配置与当前状态；相关的访问令牌、历史和低频高级项放次级分区／Tabs，不将所有编辑表单同时展开。
- 同一事实在一处编辑，摘要和其他页面读取同一来源。不让用户在 Worker、模板、集成和任务里重复填写同一模型／资源配置。
- 个人复测执行配置对普通用户可达，只显示本人范围，不请求管理员租户列表；管理员保留原有代管切换。无模型时引导现有个人模型管理，未配置时提供可操作的配置入口，不让能够自配的用户只看到“联系管理员”。执行配置与外部调用令牌权限分开，未授权页签不显示也不请求其数据；完整服务端归属规则见重设方案第 15.11.4 节，隐藏菜单不能替代鉴权。
- 保存按钮靠近所属表单，保存反馈区分处理中、成功和失败；失败保留输入，并说明配置影响新任务、排队任务还是当前执行。
- 必须清楚区分“配置已保存”“连接已验证”“实际执行可用”；没有对应证据就不显示绿色已就绪。
- 凭据采用既有受控输入与一次性展示，不预填读取到的明文，不进入 URL、普通状态消息、日志、截图或浏览器持久缓存。

### 5.6 登录、空态与异常页

- 复用全站文字、控件、间距、圆角与表面层次，保留 Arena 品牌；不另做一张与工作台割裂的营销页面。
- 空态简短说明“还没有什么”以及实际下一步；无权限、无结果、筛选无匹配、加载失败不能全写成“暂无数据”。
- 错误页面说明影响和可执行动作，详细诊断按需查看；不使用巨幅插画、无关宣传或整屏调试堆栈。

### 5.7 漏洞列表：记录下方展开详情

这是 2026-10-16 用户明确的产品决定，覆盖项目内漏洞与全局漏洞两个入口，替代右侧漏洞 Drawer；不要求其他类型详情一律退出 Drawer。

```text
漏洞标题／等级／状态／时间                         展开  更多
┌ 当前记录详情 ──────────────────────────────────────────┐
│ 标题与必要动作（复测／状态）                            │
│ 选中发现 · 关键证据／复现过程                           │
│ 宽屏请求／响应并排，窄容器切换或纵排                   │
│ 修复建议；附件／日志／历史／溯源等必要次级入口           │
└────────────────────────────────────────────────────────┘
下一条漏洞记录                                    展开  更多
```

- 默认收起；单页同一时刻展开一条，点击同条收起、切另一条替换。不并排挂载多个重型阅读器，不保留“行内 + 右侧”两套详情。
- 明确展开按钮带方向图标、`aria-expanded` 和对应详情区域关联；键盘可操作，行尾菜单、链接、复选框不冒泡误展开。收起焦点回到触发器；深链接定位时先出现真实记录，再滚动到其摘要，不强行夺走编辑焦点。
- 详情紧跟所属记录，跨完整内容宽度，不放在某个窄单元格。长标题正常换行，正文不受旧抽屉宽度限制；窄屏详情按容器纵排，只有代码／报文自身横向滚动，不让整段说明随超宽表格滑走。
- 展开选择由业务页面拥有，DataTable 只增加必要的受控展开及详情槽，不获取漏洞、不另维护选择事实。加载／失败／无权限只影响当前详情，不能吞掉列表。
- 切项、收起、筛选、翻页、切项目和路由跳转均须保留既有未保存／提交中／受理未知保护，取消离开时恢复原选择；不以卸载详情清掉复测草稿或请求身份。
- 全局漏洞 query 深链接、复测返回来源及疑似重复跳转仍可定位。不在当前筛选／分页内的定位记录以独立且明确的“当前定位漏洞（不在当前列表结果中）”条目承载同一行内详情，不混入命中数量、不静默清筛选、不把未知当删除；查无／无权限时给出局部反馈。具体实现与保护边界见本轮原方案第 15 节。

### 5.8 HTTP 数据包：Cyber 视觉语言、Burp 式报文阅读

2026-10-16 用户补充要求“放数据包的 UI 跟 Cyber 一样，有点类似 Burp”；第 15.9 节实施后用户仍不认可效果。此处按第 2.3 节两站实际报文对照形成设计，**纠正初稿“功能齐全就能接近参考”的取舍**。保留 Raw／Pretty、搜索等能力，但默认外观首先是紧凑的协议阅读卡片，而不是工具按钮围绕两个编辑器。第 15.10 节已有视觉实施回填；2026-10-18 用户带回复制和行号问题，当前定向修正与专用提示词见重设方案第 15.11 节。以下是现行设计标准，不代表所有交互均经用户验收；不从零重做阅读器，不增加代理、拦截、编辑发送或重放。

```text
┌ HTTP 证据 · 当前交互／地址摘要                            放大 ┐
├ 请求  GET   Raw  Pretty      查找 复制 ⋯ ┬ 响应 200  Raw Pretty  查找 复制 ⋯ ┤
│ 1 │ GET /example HTTP/1.1                 │ 1 │ HTTP/1.1 200 OK             │
│ 2 │ Host: example.test                   │ 2 │ Content-Type: …              │
│ 3 │                                     │ 3 │                              │
│   │ 请求正文                            │ 4 │ 响应正文                         │
└─────────────────────────────────────────┴──────────────────────────────────┘
```

这是层级示意，不按字符图固定宽度。“查找／复制／放大／更多”实际采用有可访问名称的低强调图标操作，Raw／Pretty 为轻量文字标签；Pretty 仅在支持时提供，样例方法和状态只表示实际可确认数据，不能给缺失报文补造元信息。选中态用细下划线而非大面积按钮底色，默认不展开搜索框。

- **一个完整阅读器，不是两张大卡片。** 宽容器左请求、右响应，默认等分；一个外框、共同摘要头、紧凑侧标题与正文构成一体，圆角约 10–12px，仅卡片外缘圆角，内部细分隔。共同头以约 36–40px、侧头以约 40–48px 为起点，不为固定高度裁切文字。合并已有重复交互标题／来源，不在原多层标题上再加一层；单一主交互不单独铺重复的选择按钮，多交互提供紧凑选择，补充证据仍可进入并返回主交互，来源只保留一个清楚位置。方法／状态只从已载入的有效首行提取，地址摘要仅用实际可确认的请求目标／Host 或已有明确元信息，不推测 scheme、补造成功状态或新增后端字段，默认非可点击目标。必要的缺侧、截断与读取失败在对应侧简短可见；普通文本／图片证据保留原有阅读形式，不强套 HTTP 两栏。
- **成对阅读框，而非独立编辑器高度。** 桌面双栏正文顶部／底部对齐，中央分隔线贯通。以两侧软换行后的真实渲染内容较大高度决定整对高度，再受视口上限约束；两侧都短时整对收敛，一短一长时允许短侧在同一报文表面内留白，不再各侧单独封底，也不只把外框拉高掩盖内部高度差。默认长包正文上限以约 360px 为设计起点，按视口收敛在约 280–400px；这是 Arena 设计值，不是 Cyber 全场景测量。放大／收起作用于整对阅读区，左右仍独立滚动，不强制同步位置；不固定所有短包高度、不无限撑长页面。单侧搜索或必要提示出现时处理对应栏头空间，使双栏正文起点仍平齐，不将警告藏起来换取对齐；避免以双方已被强制的视窗高度互相回写导致测量循环。
- **按实际容器适配。** 约 600px 及以上可用宽度以双栏为起点，默认软换行，优先在 620–760px 的普通详情宽度保留成对阅读；具体以两侧操作不换行、不裁切为准，不能仅沿用旧 759px 阈值。更窄时改请求／响应标签，保留身份、各侧阅读位置和搜索归属。关闭换行时，仅报文内部横向滚动。不是复制参考站的整屏媒体查询，也不强行让手机维持双栏。
- **正文像协议阅读器而非后台文本框。** HTTP 专用默认 13px／20px 等宽字，行号槽约 36–40px、浅底色及右分隔线，正文左内边距约 10–12px；这是兼顾参考密度与 Arena 可读性的局部取舍，替代本区域此前强制至少 14px 的要求，不缩小全站正文或普通编辑器。浅色以白正文、淡色标题／行号和细线分层，深色映射现有语义表面；短侧余白与正文同底色，不再在半途切换背景。沿用共享 tokens，不另建页面私有配色；Monaco 主题全局生效，报文局部颜色／密度调整须避免污染同时挂载的普通编辑器。保留系统字体及浏览器缩放，深浅模式都可读；关闭 minimap、无意义编辑提示和空白 glyph／折叠槽。首行的方法、版本、状态与头名称层级清楚，保留正文现有安全高亮，不靠整片彩色背景或把所有文本套 JSON 实现“专业感”。
- **行号位置以实际几何验收。** 数字与右分隔线之间保留约 6–8px 留白，正文侧仍留约 10–12px；约 36–40px 行号槽只是起点，不以固定宽度裁掉多位数字。仅增大 Monaco `lineNumbersMinChars` 不会给右对齐数字增加右间距，不能用它掩盖贴线问题；保留 Monaco 的行布局，不硬移整块 margin 或行号 top。基线、滚动与缩放在真实编辑器核对，软换行续行不重复逻辑行号不是错误；局部规则不污染普通编辑器。
- **复制可用性必须包含真实写入。** 点击复制取对应侧已载入原文，不取 Pretty／DOM；成功反馈在实际写入兑现后出现，按侧靠近动作并可被辅助技术感知，不能只藏在长阅读器底部。能力不可用与写入拒绝给出可执行恢复动作，手工路径明确选择 Raw；不能把手工恢复或 mock 成功说成一键复制通过。仅依据实际环境实现必要替代路径，不绕过浏览器安全，不记录复制正文或读取用户现有剪贴板。工程验收实际写入仅使用获准的非敏感样本，未执行就明确未覆盖。
- **Raw 优先，Pretty 不改证据。** 默认原文，严格保留当前可读取文本；Raw 指接口载入的未格式化文本，不自动等于完整原始字节，尤其截断或替换解码的预览不能冒称字节级保真。“格式化”仅在完整、可可靠识别的正文上提供派生视图，首轮支持 JSON 正文即可，不为凑功能实现通用协议解析器。HTTP 首行／头部保留原文顺序及重复项，格式化不回写、不补齐缺失响应、不把不同交互拼成一对；不执行 HTML、脚本或远程资源。截断、二进制、编码不可可靠识别或 JSON 无法无损解析时保持原文／既有受控原件入口，并说明不适用，不能把有损重建称为原始包。
- **工具少而可用，不默认铺满功能按钮。** 每侧标题、方法／状态与 Raw／Pretty 在同一行，右侧保留低强调的查找／复制图标；换行与原件下载等低频动作放到该侧的更多菜单，放大作为整对阅读区动作。普通非 JSON 不显示禁用 Pretty 和常驻“仅支持 JSON”横条；不适用说明可在该侧更多菜单按需查看，实际截断、解码不确定、缺侧或读取失败等证据限制仍在正文附近可见，不将所有 `reason` 一概隐藏。图标有明确可访问名称／tooltip 与至少 32px 点击区，不靠 10px 文字小按钮压缩空间。搜索按需展开，复用现有 Monaco 能力和匹配／前后跳转，范围明确为已载入文本。默认软换行对齐参考习惯，保留开关且不更改原字符串。复制不混入行号、提示或格式化结果；预览不完整时动作名称与附近提示明确是已载入片段，不暗示完整原件。原件下载继续走现有鉴权链，不新增传输通道。
- **切换稳定。** 每侧模式、搜索、滚动及模型身份与当前实体／交互／请求或响应绑定；切换不能串包、收到旧请求后覆盖新包或丢掉长报文展开入口。放大使用同一逻辑阅读状态，退出回原侧与合理焦点，不与行内收起／草稿保护冲突；不常驻挂载全表编辑器。普通表单编辑器不因报文专用只读变体改变行为，不新增依赖。

## 6. 控件与交互细节

- **按钮**：主要／次要／文字／危险层级统一；图标与文字间距固定，图标按钮有可访问名称。禁用原因不能只藏在 disabled 控件的 tooltip 中。
- **输入**：标签、当前值、帮助与错误分层，必填规则准确；不让 placeholder 代替字段标签。错误靠近对应输入，长中文说明正常换行，不推走提交按钮。
- **Select／菜单**：选项可扫读，选中、禁用、加载、无结果有文字反馈；长名称可完整访问。不能仅在鼠标悬停时才知道实际选项或限制。
- **Tabs**：用于同一对象的视图切换，不用作无关页面的第二侧栏；选中态、焦点态明确，避免每个标签都像独立的大按钮。
- **Dialog／Drawer／Popover**：按动作语义选择，资料小工具用 Popover、完整编辑用 Dialog、上下文详情可用 Drawer。关闭最上层不连带清空底层表单；焦点回到合理触发位置，Esc 与背景交互符合共享组件约定。
- **Portal**：浮层不一定继承页面祖先样式，主题、字号、层级与尺寸通过共享组件和语义变量贯通；不得出现正文是统一工作台风格、下拉和弹窗却回到另一套默认皮肤。弹窗内部触发的下拉／资料浮层应位于其所属弹窗及遮罩之上，并遵守同一焦点边界；用共享层级与组件上下文处理，不逐页堆 `z-index:99999`。当前组件对层级 token 的使用并未全部统一，不能假定已有 Popover／菜单在任何 Dialog 中都自动正确。
- **反馈与动效**：轻量反馈不抢阅读；需持续处理的错误在页面保留，不能只靠瞬时通知。以本轮实测为参考，Arena 将已有共享 fast／base 时长目标统一为约 140ms／190ms，常规进入与控件反馈采用 `cubic-bezier(.22,1,.36,1)`；这是待实施约定，当前源码仍有 100ms／160ms。hover／focus 仅过渡颜色、背景、边框和必要阴影；浮层轻量淡入或小幅位移，展开图标转向，正文内容就位稳定，不做弹跳／弹簧／闪烁或整页 `transition: all`。长漏洞详情不以固定 `max-height` 动画裁剪、不按全文高度反复触发布局或缩放 Monaco。保留 reduced-motion 的近即时切换，收起／切换后焦点与滚动不因动效丢失；不引入动画依赖。
- **键盘与可读性**：焦点可见，Tab 顺序符合内容顺序，正常缩放时仍可操作；状态不只靠颜色，关键正文与控件保证足够对比。密度目标不能凌驾于可访问性。

## 7. 响应式、滚动与数据更新

- 以扣除侧栏后的实际可用宽度判断布局，优先复用现有断点，不为每个页面发明一组不同断点。
- 宽屏不无限拉长阅读行，窄屏不强撑多栏；页面工具条和动作按组换行，优先保留名称、状态与主要操作。
- 表格需要横向滚动时只让表格容器滚动，次要列可转详情；不让整个应用横向漂移。正文换行，报文／代码在自身区域按实际阅读需要换行或横向滚动。
- flex／grid 的可收缩区域设置正确的最小尺寸与滚动边界。不能用外层 `overflow:hidden` 掩盖被裁掉的按钮、正文或浮层。
- Dialog、Drawer 和资料浮层限制在视口内，长内容独立滚动；底部操作栏不遮住最后一项，移动端软键盘出现后仍能访问关键操作。
- 刷新保留当前阅读位置、输入与选中项；后台更新不重置整页。首次加载、局部刷新、旧数据和刷新失败分别反馈，不能一次错误就把已有资料清空。
- 仅按真实业务需要更新活动记录，终态停止不必要轮询；不能为了“实时感”增加推送系统或模拟进度。

这些是静态定位，不是全站已符合规范的声明。尤其当前通用 `MarkdownPreview.vue` 仍以 `<pre>` 显示原文，不能称为排版预览；需要 Markdown 阅读效果时复用已有安全渲染，不执行资料中的脚本或任意 HTML，不改写存储原文。当前 Shell、MasterDetail 与工作区使用的响应式条件也不完全相同；按内容选择全局断点或容器条件，不能宣称现有断点已全面统一。

- 颜色、间距、字号、圆角、阴影等公共值由共享 tokens 唯一维护；共享控件的外观和状态由组件默认／明确变体表达。
- 页面负责信息组织、业务文案和必要布局，不负责另造 Button、Dialog、Select 或整套主题。已有组件不合适时修改最小共享能力，不堆连续覆盖和多层转发。
- 全站同义状态与标签保持同一表达；实体的业务语义不同，不为了复用 Badge 把不同状态压成同一个“成功”。
- 此前复测页的局部样式来自当时“不改普通页面”的实施范围，并非全站规范要求各页面都保留私有主题。后续明确做共享视觉统一时，集中到共享层并移除被替代覆盖；不长期维护两套同义变量，也不在当前文档任务中顺手改代码。
- [项目工作区方案](specs/project-workspace-ui-design.md)、[项目创建方案](specs/project-creation-input-design.md)与[漏洞复测方案](specs/vulnerability-retest-design.md)继续负责各自业务流程、状态和材料保护；通用视觉／组件约定集中在本文。旧方案的历史记录不改写成当前实现或新授权。

## 9. 实施与验收边界

1. 接到具体 UI 任务时，先确定该页主要信息、主要动作和适用模式，再核对当前共享组件；不是重新设计全站或先做一套独立效果图。
2. 在明确范围内贯通页面、共享组件和所属浮层；如果需要改共享默认值，先说明实际受影响范围，保留已有交互与普通任务行为。不以“只是换样式”忽略全站影响。
3. 优先在实际 Arena 页面直接检查受影响区域的层级、点击、焦点、阅读、滚动及必要窄屏情形。参考站截图、CSS 值相似、组件渲染或构建成功都不等于实际页面符合规范。
4. 选择最短、能判断本次改动的验证方式；不默认全量测试、浏览器尺寸矩阵或新增视觉验收平台。无需为看布局启动真实任务、访问目标或调用付费模型；验证使用非敏感资料，凭据不得进入截图。
5. 报告区分设计规范已写、代码已实现、实际系统已加载、页面已观察及用户已确认。没有现场证据的部分明确待验收，不宣称“全站已经统一”。

本规范不是每次必须逐项填写的检查表。验收核心是：**使用者能在不同功能间保持一致的操作习惯，迅速找到当前工作、有效结果和下一步动作；视觉整体接近 Cyber 工作台的克制、清晰与密度，而不是只有局部配色相似。**
