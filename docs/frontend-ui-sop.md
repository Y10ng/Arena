# 前端 UI 实施 SOP

> **2026-10-31 最新澄清：用户要求当前整体包括字体，如浏览器再缩小10%。** 本次按90%等比例显示返修，不继续分别改token；此前禁止整页zoom的取舍不覆盖这次明确要求。原astra实施会话继续负责同轮返修，不使用gpt-6.1-sol。唯一视觉要求见UI规范第3节，批次与真实进度见方案第24节。继续沿用监督／独立实施分工和已授权范围，技术交付不等于用户视觉验收。

## 1. 文档职责

- [AGENT.md](../AGENT.md)：产品、能力、业务数据与工程底线。
- [全站 UI 设计规范](ui-design-standard.md)：唯一的视觉、组件、交互和阅读标准，不并存冲突路线。
- 本 SOP：分析、独立实施、验证与交接方式，不复制主题数值。
- [全系统 UI 重设计方案](specs/global-ui-redesign.md)：本次范围、批准来源、分轮状态、实际检查及未覆盖项。

## 2. 已选方向与分工

- 保留 **U4 适度尺度 · 分组留白** 的设计；当前按明确反馈整体90%显示，正式验收使用浏览器100%，分别记录浏览器与应用缩放。不重新设计布局、不强迫全部同行，不迁入评审条、演示数据、占位菜单或本地假提交。后续新实施会话使用astra；当前父会话为astra时可通过fork继承实际模型，不传其他模型覆盖，不以提示词自称代替模型选择。
- 监督负责规范、范围、实施提示及实际页面复看；新实施会话负责正式代码和必要构建发布。同一时刻只有一个正式代码写入者，浏览器交接明确。用户已授权按此方向自动逐轮推进，不再逐批索取同一批准；实际权限受阻或超出UI边界仍报告，不借会话绕过。
- 范围含所有正式页面、项目子页、浮层、共享组件和业务局部控件。不能因共享tokens变化就把未检查消费者算作完成。
- 保留所有真实能力、权限、状态、深链、长内容与输入保护；保护现有未提交改动，基于当前文件定向修改，不批量回退。
- 历史样板已移除、专用进程已关闭；本轮直接修订正式页面，不恢复演示入口，不建立长期平行产品。

## 3. 分析与实施

1. 编辑前检查任务分支和工作区；读取AGENT、当前规范及本批方案，不重跑历史提示词或重复泛查参考项目。
2. 设计改造先从任务、信息优先级、导航和动作关系确定结构，再核对真实接口及成熟交互。主菜单保留原真实布局／分组，正文移除重复标题与无用副行；当前用户明确要求的整体90%显示只调整尺度，不借机重做既有结构。核对视口铺满、Portal位置和自研拖动的坐标换算，不将CSS缩放等同于浏览器所有布局行为完全一致。
3. 新实施会话按当前有界批次建立真实可用路径，贯通所属浮层、输入、错误、返回和完整阅读。样板未展示的页面按同类问题举一反三，不强制表格化、不保留冲突旧骨架。
4. 复用适合的逻辑和组件，删除当前批已被替代的样式、无调用呈现和失效视觉断言；保留有效测试及业务能力。不加依赖、不改后端执行内核，不重建或下载未变的Worker工具层。
5. 编码与构建串行，核对实际服务静态目录，按已有非破坏发布方法加载产物。已有正常Server／Dispatcher等服务可复用，不因前端更新盲目重启。不得清空发布目录或删除旧hash。
6. 实施者交回实际文件、检查、部署入口及未覆盖项后停写，监督复看；发现具体阻塞返修，完成本批后继续下一批。不得将构建通过或自己的检查冒充用户视觉认可。

## 4. 验证

### 正式界面

以最新用户反馈和当前设计规范检查布局、区域比例、信息层级、字阶、颜色与交互，不冻结历史样板。真实能力须放到合理位置，不复制虚构业务，不以参考示例功能少为由删掉正式功能。

正式代码变化后按AGENT完成构建并确保完整系统可用。确认浏览器实际加载新产物，而不是只构建到未被服务使用的目录。监督在最大化或等效桌面视口直接操作并查看整页截图，记录实际CSS尺寸及缩放；本轮目标1920×1080、浏览器100%，不能把截图像素冒称CSS视口。不默认增加移动端矩阵，不删除已有适配。

每批覆盖代表完整路径及共享改动的必要消费者。设计与功能保留分别判断；若仍有重复头、正文被压低、错误字阶、历史下拉、设置挤位或文章式复测等已知问题，继续返修，不靠文件数量结案。真实数据不足如实记录，不伪造正式响应或插入样例。

默认不运行全套自动测试；直接操作不能覆盖的具体风险才补定向检查并说明原因。构建已有类型检查时不重复跑typecheck，不将lint、单元、组件和浏览器矩阵当默认套餐。

不为UI验收创建项目／启动计划／研究／复测，不调用模型或连通性测试，不访问目标，不上传、删除、保存配置或改变业务生命周期，不生成报告。允许正常授权登录和只读查看已有数据；凭据及敏感正文不进入日志或截图。保留业务按钮不等于获得执行这些动作的授权。

## 5. 每批记录与收尾

- 分开记录规范已写、代码已实现、正式系统已加载、界面已观察、业务动作已验证、用户已认可，不合并成“全部通过”。
- 记录当前分支、本批文件、真实检查结果、未覆盖项、是否提交；完成前审阅git diff。
- 未授权commit／push，不顺带修改发布方式或扩展安全研究能力。
- 用户要求持续推进至交付，不在无实际阻塞时停在“等下一轮批准”。中断则从方案最新真实记录续接，不虚构常驻后台监督服务。
- 收尾核对本轮进程归属，结束已完成且无用途的构建／预览进程，关闭自建验证页和已退出实施任务；不得批量pkill、杀用户浏览器或停止正常Server／Dispatcher／数据库／Worker。保留正式入口可直接验收。
