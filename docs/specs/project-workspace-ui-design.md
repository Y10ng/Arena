## 3. 推荐设计

### 3.1 五标签，保留现有主工作区

导航顺序调整为：**图谱、运行、漏洞、产物、提示**。

- 移除目标、溯源、覆盖、Payload 四个项目标签和实际项目页面路由，不只是 CSS 隐藏；不移到「高级功能」里继续占据项目详情。
- 五项使用一条统一导航，不再显示原探索过程／成果分组的装饰分隔点。复用路由链接和选中态，不为统一外观替换为只适用于本地面板切换的 Tabs 状态。
- 保留现有图谱默认入口、五个保留页面的路由名称、深链接参数和页面本体。本轮不新增「概览」页，也不更改打开项目时的默认落点。
- 原徽标保留已有语义；不把 Intent 数包装为实际活动 Run 数，不把漏洞记录数标成已确认漏洞数。不添加覆盖率、研究完成率或无依据的进度条。

### 3.2 顶栏按操作频率分层

建议结构（示意，不代表已渲染的截图）：

```text
返回  项目名称                         查看成果  暂停/继续  结束并生成报告  更多
      项目短状态（如已完成／已暂停）；必要动作反馈只在对应操作位置
      场景                            项目信息（按需展开）

图谱    运行    漏洞    产物    提示

当前页面内容，占据主要阅读与操作空间
```

- 移除重复的「工作空间」小标签，保留项目名称就地编辑与保存反馈；使用现有字号 tokens，不以超大标题制造层级。
- 「查看成果」作为稳定的成果入口；暂停／继续、结束并生成报告、重新开启及必要重新授权仍依据原条件提供。示意图不要求不存在的动作一直显示，也不新增生命周期。
- 将 Workers、资料、两项现有导出和删除项目收拢到一个带文字的「更多」菜单。Workers 和资料仍打开原对话框；导出仍调用原处理；删除独立分组、保留危险语义与二次确认。不用新建设置页或嵌套多级菜单。
- 「结束并生成报告」保留直接入口和原确认／等待静默语义，不改成点击即可断言停止或成功。生命周期动作的禁用原因在动作附近可见，不能只存在于 disabled 按钮 tooltip。
- **2026-10-19 取舍更新：**取消项目组信息和移动组动作，不改名移入「项目信息」。场景保留为紧凑次级信息；管理员现有租户名称、ID、所有者仍按需查看，不改变角色可见范围。组分类关系退场不要求删除项目本体或来源材料，完整迁移范围见重设方案第 15.14 节。
- **2026-10-16 替代旧取舍：**项目列表与工作区标题始终用元数据 `project.status`，共用“待启动／进行中／已暂停／已结束／已完成”短标签，不加“上次状态”、runtime 刷新失败副标题或 Dispatcher 常驻警告，也不另建 tooltip／折叠区继续展示。`active` 仅指项目活跃，不承诺进程已运行；`paused` 不等于全部执行已清理。
- runtime 保留必要的诊断、资料修改、授权、重开、报告等待等真实消费者；未知／失效观测不能用来断言动作安全，未确认请求和动作失败仍在对应操作处反馈。项目元数据本身读取失败也不隐藏。此前 2026-10-15 只取消正常刷新提示、第 14 节保留“上次状态”的要求已被本次明确产品决定替代；不是旧实施漏做。当前实现与最短验证统一见[重设方案第 15.3 节](vulnerability-evidence-retest-redesign.md#153-项目状态项目事实与执行诊断分离)，不重跑第 14 节。
- 调整只限详情壳必要的比例、留白与操作布局；保留深浅主题语义色、Lucide、焦点反馈及现有浮层。无渐变大卡片、装饰图、额外动画或新设计系统。
- 以含侧栏后的真实工作区宽度处理换行；长标题、长原因不得挤掉动作。导航、内容、浮层各自滚动合理，不通过外层裁切掩盖溢出。

### 8.1 使用目标与本轮取舍

用户希望取消列表方框，改成可查看详情的时间线；执行时看得懂当前工作与工具活动，结束后看到结果，不被协议拒绝、内部修正与重试报错刷屏。推荐 **工作进展时间线 + 按需工具过程 + 完整运行详情**，而不是给旧 Run 列表左侧加一条线，也不是把 stdout 按行搬进时间线。

- 主线回答：在做什么、已经得到什么、现在是否还在推进；不展示 Prompt、模型内部思考、协议 JSON、堆栈或每条 Shell 输出。

- 这是可读性与运行透明度改造，不承诺提升漏洞发现能力；不改变执行策略、错误接受规则、恢复次数、授权、项目控制、模型或 Prompt。

### 8.3 信息布局与交互

这是按发生顺序阅读的事件界面，不是按时长比例绘制的图表，不新增统计卡、百分比、固定“侦察→扫描→验证”阶段或第二套配色。

1. **单一连续时间线。**细竖线、时间锚点、工作标题与正文直接排在工作面上，不为每条节点套边框、阴影和背景卡片。默认新工作在前，按首次真实发生时间稳定排序；结束／刷新不把旧工作重新置顶，无时间依据的不编造时间。多 Worker 可以并行，不能由纵向顺序暗示彼此依赖。
2. **节点的三个层次。**主行是业务目的与一个短状态；执行中正文是已经记录的当前工具活动，结束后正文优先展示已有结果；次要操作是“工具过程”“执行记录”“查看详情”。Worker、内部类型、优先级、Run／Session ID 收入详情，不再占主线多行标签。活动开始／结束更新同一调用，不生成两张重复条目。
3. **进行时只说已观测到什么。**有开始且无对应结束时显示工具正在执行；并行调用不可只保留最后一个而隐藏其他在途调用。只有完成记录时显示“最近完成”，不能反推曾实时观察到开始；没有事件时只显示 Run 的真实“执行中”，不编造正在思考、正在访问某目标或进度百分比。工具名、调用时间、短状态和耗时足够，原始参数、命令、输出与错误只在受控详情查看，不从任意 payload 猜测可公开摘要。
4. **完成后结果优先。**使用已接受且关联可靠的 Fact／正式结果／已有成果入口；长结果提供全文，不改写权威文本，也不额外调用模型生成摘要。只有进程完成时显示“执行结束，结果未确认”，不说结果已接受。节点内的结果只代表这一项工作；项目整体完成仍以项目权威状态为准，已有漏洞成果与项目文件承载交付，不新造“最终安全结论”。
5. **详情保留完整性。**节点可展开工具过程与真实执行记录；具体 Run 的“查看详情”继续进入原有宽阅读器，保留 `?runId=` 精确定位、错误全文、命令审计、关联资产及原件。当前选中 Run 不因新增运行被自动换掉；返回恢复节点、筛选与阅读位置，不要求新建 Drawer 或另一套日志阅读器。
6. **保留检索能力而不混淆状态。**搜索仍明确限定元数据与已有结果，不冒称全文日志搜索。原执行状态筛选可以保留，但标签为“执行记录状态”；聚合节点命中时指出命中的执行并可定位详情，不能把其中一次 failed 当作整个工作最终失败，也不能只因另一次成功就把失败历史从筛选中移除。
7. **刷新不抢阅读。**沿现有刷新节奏更新已展示事实、去重和保持稳定 key；用户阅读旧记录时不强制滚回最新，只给“有新进展／回到最新”的轻入口。工具摘要优先读取当前活动 Run，历史过程按展开读取；不为每条历史记录下载原始日志，不增加每节点定时器或全历史高频请求。
8. **诊断是独立阅读层，不是被删除的数据。**内部协议拒绝、工具错误、恢复细节保留在对应尝试／调用的诊断中。请求失败、数据陈旧、结果未知仍在所属读取区域可见，不能把页面刷新失败当成可忽略的执行噪声；不凭错误字符串猜测“已恢复”“已吸收”或“正在重试”。

视觉沿用全站现行 tokens、简体中文、Lucide 与应用 90% 尺度，状态有文字／图标，不只靠颜色。保留键盘展开、焦点返回和明确滚动容器；不改全局导航、主题、比例或其他业务页。上述是新目标设计，不宣称现有界面已经具备这些行为。

### 8.4 纠正“报错都会吸收后重试”与“前端已经能实时读工具”的判断

1. **工具事件已产生，但目前在收尾后才入库。**`container/pi-agent/src/runner.ts:558–589` 订阅真实 `tool_execution_start/end`，带同一个 `tool_call_id`，通过 stderr JSONL 立即输出；`dispatcher/tasks/process_runner.py:619,833–835` 却是在 `process.communicate()` 返回后才调用 `record_pi_tool_events`。`tasks/hook_records.py:61–85,98–127` 将其投影为 `hook_operation`，保留 `operation_id/session_id/phase/recorded_at`。因此“读取 hook-events + 每 4 秒轮询”只能改善历史工具过程，**不等于已经实现执行中进展**；本轮目标需要贯通增量观测，不把这项缺口留成永久“暂无数据”。
2. **当前可展示的是工具元数据，不是实时工具输出。**pi 审计只带工具名、调用身份、开始／结束、错误标记、字节数等，不复制参数或输出正文（`hook_records.py:82–85`）。现有类型里的 `tool_input/tool_response` 不证明 pi 已填充这些内容；`command_started/finished` 是外层 Worker 进程而非内部工具。UI 不反向解析 stdout、session 或 Prompt 去凑“智能进展”。本轮不承诺逐 token、终端全文或工具输出增量直播。
3. **有局部有界修正，不是全部故障必然恢复。**`container/pi-agent/src/submission.ts:183–194` 只将缺提交、提交无效和指定 Artifact 问题列为本地可修正；`runner.ts:697–707` 在同 session 和剩余边界内修正，遇到 providerError、冲突等不会走同一修正循环。“不要重做已完成动作”是提示要求，不是所有执行都不重复目标操作的程序保证。
4. **保存材料、重放写回、重新运行、业务接受不同。**本地提交仍有 `server_accepted:false`（`runner.ts:365–380`）；candidate spool／outbox 留存不等于 Fact 已接受（`dispatcher/tasks/candidate_intake.py:690–772`）。`conclude_writer.py:357–448` 只对指定瞬态响应重放写回；确定性拒绝不能自动说成“已重试”。特定 fresh retry 会携带失败／材料上下文，不证明每次新 Run 都吸收全部历史输出。现行 `artifact_records.py:155–161` 对进程失败也不会发布所有原始 stdout/stderr；本轮保留现有可读材料和边界，不承诺补回未保存原文，不绕过既有输出保护。
5. **后续能重试不等于已安排重试。**`delivery_retry_route.allowed/retry_at` 是准入／冷却信息，不是排队承诺；实际后续 Run 或明确来源关系才支持展示后续执行。`TaskRun.failed/timed_out` 只说明本次尝试，任务最终失败要看所属 Intent／attempt 的权威结论。没有确切恢复关系时不写“已恢复”，即使同一 Intent 后续已有成果，也应表达为“该工作已有结果；查看此前执行”，不改写旧 Run。
6. **时间和缺失必须按事实表达。**`server/services/audit_events.py:127–143` 的 hook `recorded_at` 才是工具发生时间，外层 `ts` 是服务端入库时间；收尾批量写入不能伪装成刚刚执行。配对键须包含实际 Run、phase、session 与 operation_id，不能只按工具名／数组相邻配对。只有开始、没有结束且 Run 已终态时显示“结束状态未记录”，不保持虚假的工具运行中；采集／读取未知不推断为没有调用。

### 9.4 目标界面与阅读行为

**固定左右工作面，而不是“先列表、再进入另一整页阅读”。**

```text
项目上下文与既有六项导航（其中“文件”选中）

workspace                         当前相对路径                 刷新 / 下载
/home/kali/workspace               ─────────────────────────────────────
  可折叠目录                       当前文件预览
    文件                           文本 / Markdown / 图片
  文件                             或如实显示不支持预览与下载入口
```

示意中不虚构具体目录或文件；正式树节点全部来自实际目录读取。

1. **左树约 280–320 逻辑 px，右侧弹性占满剩余区域。** 延续现有缩放，两侧独立滚动，正文尽早出现；可复用 `MasterDetail` 的 fill-height 结构，不另造工作区框架。点击文件仅更新右侧，目录始终保留。窄窗沿已有适配，不新增移动端矩阵或拖动分栏工程。
2. **去掉三类按钮及旧类型筛选。** 不把它们搬进更多菜单或折叠分类；导航“文件”与真实 workspace 根足以说明对象。最少工具是刷新、所选文件原件下载及已有预览模式；搜索如保留，明确只过滤已加载节点并保留父路径，不能暗示全 workspace 搜索。无需目录统计、全量文件数或额外说明卡。
3. **文件夹与文件职责清楚。** 目录展开／折叠，文件选中后预览；目录先于文件，同级按稳定文件名排序。树 key 使用项目＋真实工作区身份＋相对路径，不只用 basename。同名不同目录不串选；空目录、尚未展开、分页未加载与读取失败不能混为一类。
4. **键盘与阅读位置。** 上下移动、左右展开／收起，Enter 选择文件，焦点与选中可辨认；长名在右侧路径完整可读。刷新保留仍存在的展开、选中和滚动位置；对象消失就如实提示，不自动打开同名其他文件。快速切文件／切项目的晚响应不得覆盖当前预览。
5. **预览复用现有能力，不改原件。** 文本／代码沿只读 Monaco；Markdown 沿已有安全渲染并可切原文；图片沿受控内容读取。二进制或不支持类型显示大小与下载，不强行解码、不执行 HTML／SVG 脚本，不经外部预览服务。长文本显示真实 head/tail 窗口、字节数和截断事实，下载取完整原件；当前文件可能仍在写入，不将本次读取宣称为原子归档快照。
6. **页面和来源身份分开。** 当前工作目录文件默认无 Artifact／正式报告身份，不编造 hash、接受状态或 TaskRun。需要的文件类型／大小／修改时间来自该次文件读取。只有真实保存记录才显示既有 Artifact hash 与来源。
7. **无工作区不是空目录。** 尚未创建运行环境、原目录不可达、owner 离线／归属不明、无权限、已删除与真实空目录分别反馈。页面读取不得启动、恢复、解冻或重建容器；已 stopped 不自动标成“归档”，仍读实际留存目录。

### 9.5 最小完整后端与数据边界

1. **新增有实际消费者的只读 workspace 能力。** 在项目权限下提供根身份、单层目录枚举、有限正文预览、单文件原件下载；语义为 `project + workspace identity + relative path`。复用既有鉴权、HTTP 和读取组件，不改变 Artifact API 的含义、不把每次列目录登记成 Artifact、不新增通用文件平台或文件数据库。
2. **先核验实际部署，再选择最短读取位置。** 当前本地部署优先在能访问实际 Docker 宿主的后端读取：核对项目／实例／容器完整身份及真实 Mounts，将研究 workspace bind 解析到受控宿主目录；当前控制容器和 executor 共享它，只展示一次。可复用现有 Docker client／材料校验能力，不把 daemon、任意绝对路径、环境变量或 inspect 原文暴露给前端。若 Server 实际不在该文件系统／daemon，先明确这个具体接缝，不能猜根、返回空成功或借此建设远程文件网关。
3. **当前 bind 目录贯通 active／paused／stopped。** 目录枚举和文件读取直接用受约束宿主文件描述符，不依赖 `docker exec`，不调用 `prepare/ensure_running` 等会创建／启动／同步的动作。不另加“先暂停才能看文件”的使用门槛。
4. **历史覆盖不靠静默猜测。** 对实际查到的无 bind 历史容器，用明确的真实来源判断。现有 Docker archive 可以读取静止 layer，只有本轮确有该消费者时才定向复用；不得用解冻／启动补读取，也不为假想旧环境默认新增整套 fallback。若尚未支持某类真实历史根，必须显示明确未支持而非空目录，保留原 Artifact／运维材料读取入口，并在交付说明未覆盖；不能宣称完整历史目录已交付。
5. **单层按需、有界返回，不先递归下载全目录。** 初次只列根，展开才列子目录；目录较大时可继续加载下一段，明确 `has_more/cursor`，不静默丢掉上限外文件。文本窗口复用当前合理容量与截断语义，文件下载流式读取，不在 Server 或浏览器将整个 workspace 打包进内存。首轮不用自动高频轮询、全文搜索索引或全量归档任务。
6. **限制来自实际可达泄漏路径。** 执行中的工具能创建 symlink 指向控制区，历史 workspace 中可能存在 `.cairn/pi` 私有 session；因此不能只 `resolve()` 检查后重新按路径打开。借用已有逐层 `O_NOFOLLOW`／普通文件／硬链接与挂载边界处理，目录、预览、下载共用同一规则。链接可按不跟随的节点提示，不能穿越 workspace、其他项目或私有挂载；不接收任意宿主路径或开放容器根目录。
7. **按真实私有位置阻止输出，不一刀切隐藏合法文件。** 保护控制/session、model binding、出口私钥等平台私有材料；已有 CLI 的 `_PRIVATE_PARTS` 不能照搬成任意文件名黑名单。`.cairn/artifacts/registered` 是合法工作文件版本，不因 `.cairn/pi` 私有就把整棵 `.cairn` 隐藏。根外 `/home/kali/.cairn`、`/tmp/cairn-prompts`、执行 socket、capture/egress 私有目录不纳入树；不为了做界面改写原件或扫描所有用户正文。
8. **保留现实来源和旧消费者。** 运行日志页、全局正式报告、项目资料继续读现有接口；不把它们重新复制进 workspace。`artifactId` 深链由运行时间线、图谱及报告 Dialog 真实使用（`useRunsPage.ts:658–663`、`GraphPage.vue:772–775`、`ProjectReportDialog.vue:546–550`），本轮仍可在右侧读取对应已保存原件，明确来源。没有可核实 workspace 路径时左树不伪选、不按同名猜文件；不为保深链保留旧分类页或新增假目录。项目／Artifact 身份检查、原文、截断、原件下载和真实来源不丢。

主要接点：`ArtifactsPage.vue/.css`、`artifactsModel.ts` 及直接 API/types，`navigationRegistry.ts`／项目导航名称，必要只读树组件；后端新增局部 workspace reader/route，复用 `runtime/materials.py` 的有效底层规则与实际根归属。旧专属分类投影和失效测试应替换，不顺带删除仍被报告／流量／漏洞使用的 Artifact 服务。

示意只表达信息层级，不要求增加说明文字。具体行为如下：

1. **一个外框、一条分栏线、各自滚动。**筛选工具区与主体有轻微分隔；左侧约 340–380 逻辑 px，右侧弹性占满。工作行之间用留白和细分隔线，选中行用浅底与清楚焦点，不恢复逐节点卡片、阴影和时间线装饰。左列表、右正文、代码／终端各自拥有正确 `min-height:0` 与滚动归属，不能用外层裁切掩盖溢出。

3. **右侧只有“结果／执行记录”两个主视图。**“结果”展示该工作全部已接受结果及真实来源 Run，原文自然换行、完整可读；“执行记录”展示一个明确选中的 Run。选择工作默认进入执行记录和最近一次**命中当前筛选的** Run，结果视图可由用户主动切换；后台刷新不得替用户切 Tab、换 Run 或把失败筛选下的选中项改成另一次成功 Run。
