## 3. 推荐设计

### 3.1 五标签，保留现有主工作区

导航顺序调整为：**图谱、运行、漏洞、产物、提示**。

- 移除目标、溯源、覆盖、Payload 四个项目标签和实际项目页面路由，不只是 CSS 隐藏；不移到「高级功能」里继续占据项目详情。
- 五项使用一条统一导航，不再显示原探索过程／成果分组的装饰分隔点。复用路由链接和选中态，不为统一外观替换为只适用于本地面板切换的 Tabs 状态。
- 保留现有图谱默认入口、五个保留页面的路由名称、深链接参数和页面本体。本轮不新增「概览」页，也不更改打开项目时的默认落点。
- 原徽标保留已有语义；不把 Intent 数包装为实际活动 Run 数，不把漏洞记录数标成已确认漏洞数。不添加覆盖率、研究完成率或无依据的进度条。

### 3.2 顶栏按操作频率分层

建议结构（示意，不代表已渲染的截图）：

```text
返回  项目名称                         查看成果  暂停/继续  结束并生成报告  更多
      当前状态与原因；必要的未知、刷新失败或授权提示
      项目组 / 场景                    项目信息（按需展开）

图谱    运行    漏洞    产物    提示

当前页面内容，占据主要阅读与操作空间
```

- 移除重复的「工作空间」小标签，保留项目名称就地编辑与保存反馈；使用现有字号 tokens，不以超大标题制造层级。
- 「查看成果」作为稳定的成果入口；暂停／继续、结束并生成报告、重新开启及必要重新授权仍依据原条件提供。示意图不要求不存在的动作一直显示，也不新增生命周期。
- 将 Workers、资料、两项现有导出和删除项目收拢到一个带文字的「更多」菜单。Workers 和资料仍打开原对话框；导出仍调用原处理；删除独立分组、保留危险语义与二次确认。不用新建设置页或嵌套多级菜单。
- 「结束并生成报告」保留直接入口和原确认／等待静默语义，不改成点击即可断言停止或成功。生命周期动作的禁用原因在动作附近可见，不能只存在于 disabled 按钮 tooltip。
- 项目组、场景保留为紧凑次级信息；管理员现有租户名称、ID、所有者移入可展开的「项目信息」，不改变角色可见范围、不删除原值。
- 复用现有短状态与原因，未知、旧快照／刷新失败、未确认停止等警告仍在折叠态可见。不为压缩头部吞掉诊断或将失败替换成普通运行中。
- 调整只限详情壳必要的比例、留白与操作布局；保留深浅主题语义色、Lucide、焦点反馈及现有浮层。无渐变大卡片、装饰图、额外动画或新设计系统。
- 以含侧栏后的真实工作区宽度处理换行；长标题、长原因不得挤掉动作。导航、内容、浮层各自滚动合理，不通过外层裁切掩盖溢出。

## 4. 页面移除边界

### 4.1 必须贯通的前端消费者

1. 工作区标签及删除后无人使用的目标／覆盖计数、导入、样式。
2. 四个项目路由及对应页面导航注册、命令面板、面包屑等直接消费者；实施时检索四个路由名称与路径，不能只改 `ProjectWorkspace.vue`。
3. 漏洞详情的现有「执行溯源」快捷项改为打开已有全局 `Provenance`，在 query 显式携带 `projectId`，保留原 `vulnerabilityId / observationId / runId` 选择；文案明确「在全局溯源中查看」。不再生成 `WorkspaceProvenance` 链接，不新建隐藏项目页或兼容路由。保留来源 Fact、发现 Run、复现内容、Observation、Verification、证据产物及其直达入口。
   - 本次设计纠正：最初考虑直接删除该快捷项，补查发现抽屉也被全局成果中心复用，且全局溯源已支持定位参数；因此改用现有全局入口，避免项目删页连带削弱全局详情。这里保留的是已有上下文证据入口，不是将四个退场标签整体搬到另一菜单。
4. 四页独占的前端页面／辅助文件在确认无其他调用方后删除；共享文件只删项目专属分支，不按目录名批量删除 API/types 或共用工具。删除文件后同步清理显式文件清单、格式化命令或构建引用。
5. 调整受影响的既有导航、组件和路由检查；删除只验证已退场页面的用例，保留其覆盖到的共享行为检查。不为维持旧检查保留假路由或隐藏页面，不新增静态字符串验收体系。

### 4.2 必须保留

- 全局溯源页及其仍在使用的组件/API。用户本轮要求是项目详情删页，不默认扩展到全局导航删除。
- 项目 Origin／Goal 的输入、图谱与执行使用的事实、目标数据、授权范围和资源边界。
- 后端 Coverage、溯源、Payload 的 API、模型、执行逻辑、导出内容和历史记录；本轮不评价其整体去留，也不因页面退场更改报告质量判断。
- 漏洞详情已有证据链、独立验证、候选／确认等状态区别；原始产物及证据下载。
- 项目控制、Worker 重绑、资料、授权、成果报告的既有权限与业务行为。

本方案需用户知晓的取舍：项目内四页的专有浏览／人工操作入口不再提供，包括目标页手动添加／批准／拒绝、覆盖明细浏览和 Payload 专有列表／JSONL 导出；不承诺换个位置保留全部功能。目标页不是空壳，删除是产品范围取舍，不是证明其功能不存在。底层材料与执行能力不因此删除，也绝不能用自动批准目标或放宽授权范围来弥补入口退出。尚未查证真实项目是否依赖这些人工入口；若实施时发现会阻断现有必要工作，说明具体证据并停在这个决策点，不自行新增替代流程。

旧四页 URL 按现有未找到页面处理，不新增兼容重定向、自动修复或空占位页面。仓库内不能继续生成这些链接；外部书签失效是本次删页的已知变化。当前已有全局 `NotFound` 路由（`router/index.ts:149-153`），最终匹配行为仍需实施后核对。

4. 优先在一个已有项目详情做直接页面验收，不新建付费探索：

   - 顶栏主次清楚，更多菜单能打开原 Worker／资料对话框和原确认入口；检查不等于实际提交变更，不点击确认去改变项目状态或删除数据。
   - 用实际侧栏宽度检查窄布局、一个长标题／长原因场景、菜单和内容滚动，切换现有主题检查对比度与焦点。没有对应数据时明确未覆盖，不改业务材料凑样本。
5. 运行代码改动由实施会话按当前部署文档完成必要构建并启动完整系统，确认用户实际入口已加载；纯前端改动不重建 Worker 镜像。构建已有类型检查，不额外重复；不自动运行测试套餐。
6. 不自动创建、恢复、重跑项目，不访问目标、不调用付费模型、不清库。若构建启动会影响正在执行的项目，先说明具体影响并协调，不以部署为由扩大任务操作授权。
